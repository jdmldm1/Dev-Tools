GitHub CLI Cheat Sheet

GitHub CLI gh

Tap any command to copy it. Values in orange are yours to replace.

Key concepts

gh vs git

git manages commits and branches locally. gh talks to GitHub: PRs, issues, Actions, releases. Use them together.

Repo context

Inside a clone, gh infers the repo from your remotes. Elsewhere, add -R owner/repo. With a fork, pick the target once using gh repo set-default.

Grammar

gh <noun> <verb> [args] [flags]. Example: gh pr merge 42 --squash. Add --help to anything.

Interactive or scripted

Omit flags and gh prompts you. Pass every flag (or set GH_PROMPT_DISABLED=1) for scripts and CI.

Structured output

--json fields returns JSON; add --jq to filter or --template for Go templates. Run --json with no fields to list them.

Hosts & Enterprise

Auth is stored per host. Use --hostname at login and GH_HOST to target a GitHub Enterprise Server.

Escape hatch: gh api

Anything the CLI lacks, call REST or GraphQL directly, already authenticated. {owner} and {repo} fill in from context.

Make it yours

Aliases shorten long commands. Extensions (gh-* repos) add new top-level commands.

Pull requests gh pr

gh pr create --fillTitle and body from your commits
gh pr create -B main -t "title" -b "body" -r alice -l bugBase, title, body, reviewer, label in one shot
gh pr create --draftOpen as a draft
gh pr list --author @me --state openFilter by author, state, label, base
gh pr statusPRs for your branch, by you, and awaiting your review
gh pr checkout 42Check out a PR locally (works for forks)
gh pr view 42 --commentsRead the PR and its discussion
gh pr diff 42 --name-onlyChanged files (drop the flag for the full diff)
gh pr checks 42 --watchLive CI status
gh pr review 42 --approveApprove
gh pr review 42 -r -b "Please add tests"Request changes with a note (-c to just comment)
gh pr comment 42 -b "LGTM"Add a comment
gh pr edit 42 --add-label ready --add-reviewer bobChange labels, reviewers, title, base
gh pr ready 42Mark a draft ready for review (--undo to revert)
gh pr merge 42 --squash --delete-branchMerge; also --merge or --rebase
gh pr merge 42 --auto --squashMerge automatically once checks and reviews pass
gh pr close 42 -c "Superseded by #50"Close with a comment; reopen with gh pr reopen
gh pr update-branch 42Bring the PR branch up to date with its base

Scripting with JSON --json · --jq · --template

gh pr list --jsonNo fields given: lists every available field
gh pr list --json number,title,authorRaw JSON output
gh pr view 42 --json state --jq .statePull out one value
gh issue list --json number,labels --jq '.[] | select(.labels[].name=="bug") | .number'Filter with jq (built in, no install needed)
gh pr list --json number,title --template '{{range .}}#{{.number}} {{.title}}{{"\n"}}{{end}}'Go template formatting
gh run list --json databaseId,conclusion --jq '.[] | select(.conclusion=="failure") | .databaseId'IDs of failed runs
Templates also offer helpers such as tablerow, timeago, color, and truncate.

Raw API gh api

Environment variables for CI & scripts

GH_TOKENAuth token; overrides stored login (ideal in CI)
GH_ENTERPRISE_TOKENToken for GitHub Enterprise Server hosts
GH_HOSTDefault host when not in a repo
GH_REPODefault repo, like -R on every command
GH_PROMPT_DISABLEDNever prompt; fail if input is missing
GH_PAGERPager for long output (set to cat to disable)
GH_EDITOREditor for bodies and messages
GH_DEBUGVerbose logs; "api" also logs HTTP traffic
NO_COLORDisable colored output
In a workflow: env: GH_TOKEN: ${{ github.token }} then call gh in any step.

Handy flags work on most commands

-R owner/repoTarget another repo
-w, --webOpen in the browser instead
-L, --limit NHow many results to list (default 30)
-s, --stateopen, closed, merged, all
-S, --searchGitHub search query on list commands
-a / -l / -mAssignee, label, milestone
@meShorthand for your own login
-y, --yesSkip confirmation on destructive actions
--helpUsage, flags, and examples
