glab cheat sheet

Connect to GitLab.com or a self-managed instance, then run issues, merge requests, pipelines, variables and releases from the terminal. Tap any command to copy it.

glab <command> <subcommand> [flags]·glab <cmd> --help
ConnectMRsCI/CDIssuesAPIConcepts

Everyday loop issue → merge

The typical feature cycle, start to finish, without opening a browser.

Pick up work

glab issue list --assignee=@me

Branch from issue

glab mr create --related-issue 42 \ --create-source-branch --draft --fill

Commit & push

git commit -am "fix: retry" git push

Watch pipeline

glab ci status --live glab ci view

Ready for review

glab mr update --ready \ --reviewer alice,bob

Merge

glab mr merge --squash \ --remove-source-branch --auto-merge

Install setup

Single Go binary. No admin needed if you drop it on your PATH.

brew install glab
macOS / Linux (Homebrew)
winget install glab.glab
Windows (winget)
scoop install glab
Windows, per-user, no admin rights
go install gitlab.com/gitlab-org/cli/cmd/glab@latest
From source with Go
glab version && glab check-update
Confirm install, look for updates
glab completion -s bash > ~/.glab-completion.sh
Shell completion: bash, zsh, fish, powershell
Offline / air-gapped: download the release archive for your OS from the gitlab-org/cli releases page, extract glab, and copy it into the bundle or onto PATH.

Connect & authenticate auth

Every command needs a host and a token. Log in once per host.

Log in

glab auth login
Interactive: pick GitLab.com or self-managed, browser or token, SSH or HTTPS
glab auth login --hostname gitlab.example.mil
Self-managed instance
glab auth login --hostname gitlab.example.mil --token glpat-xxxx
Non-interactive with a personal access token
glab auth login --stdin < token.txt
Read token from a file or pipe, keeps it out of shell history
glab auth status
Show which hosts you're logged in to and token health
glab auth logout --hostname gitlab.example.mil
Remove stored credentials

Token scopes (PAT)

apiwrite_repositoryread_user

Create at User settings → Access tokens. api covers nearly every glab command.

Environment variables (CI, scripts)

export GITLAB_TOKEN=glpat-xxxx
export GITLAB_HOST=https://gitlab.example.mil
Override config; ideal in pipelines and containers

SSH vs HTTPS for git

glab config set git_protocol ssh --host gitlab.example.mil
Clone and push over SSH
glab ssh-key add ~/.ssh/id_ed25519.pub -t "work-laptop"
Upload your public key to your profile
ssh -T git@gitlab.example.mil
Test: prints "Welcome to GitLab, @you!"

Self-managed & certs tls

Internal GitLab behind a private CA (DoD PKI, corporate root) will fail TLS until glab trusts it.

glab config set ca_cert /path/to/ca-bundle.pem --host gitlab.example.mil
Trust a custom CA bundle for one host
glab config set api_protocol https --host gitlab.example.mil
Force HTTPS for API calls
glab config set skip_tls_verify true --host lab.local
Throwaway lab only. Never on real systems
export HTTPS_PROXY=http://proxy.example.mil:8080
glab honors standard proxy variables
Host resolution: inside a repo, glab uses the host from the git remote. Outside a repo it falls back to GITLAB_HOST, then the config default. Use -R host/group/project to be explicit.

Merge requests mr

Run inside the repo; glab infers project and branch.

Create

glab mr create --fill
Title & description from commits, push branch, open MR
glab mr create -t "Add retry" -d "Closes #42" -b develop --draft
Explicit title, body, target branch, draft
glab mr create --reviewer alice --assignee @me -l backend --remove-source-branch --squash-before-merge
Reviewers, labels, merge options up front

Find & review

glab mr list --reviewer=@me
Waiting on your review
glab mr list --assignee=@me --draft
Your drafts
glab mr checkout 123
Check out MR !123 locally
glab mr diff 123
Show the diff
glab mr view 123 --comments
Details plus discussion
glab mr note 123 -m "LGTM after tests"
Comment
glab mr approve 123
Approve (glab mr revoke to undo)

Finish

glab mr update 123 --ready
Mark draft as ready
glab mr rebase 123
Server-side rebase onto target
glab mr merge 123 --squash --remove-source-branch
Merge now
glab mr merge 123 --auto-merge
Merge when the pipeline succeeds
glab mr close 123   # or reopen
Close without merging

Pipelines & jobs ci

glab ci and glab pipeline are the same command.

glab ci status --live
Current branch pipeline, refreshing until done
glab ci view
Interactive TUI: browse stages, read logs, retry or cancel jobs
glab ci list --status=failed
Recent failed pipelines
glab ci run -b main --variables DEPLOY_ENV:staging
Trigger a pipeline with variables
glab ci trace
Pick a job and stream its log
glab ci retry 98765
Retry a job by ID
glab ci cancel pipeline 4567
Cancel a running pipeline
glab ci lint .gitlab-ci.yml
Validate CI config against the server before pushing
glab ci config compile
Show fully merged config with includes expanded
glab job artifact main build
Download artifacts from job "build" on main

CI/CD variables variable

Project scope by default; add -g group for group variables.

glab variable set API_KEY "s3cr3t" --masked --protected
Hidden in logs, only on protected branches
glab variable set KUBECONFIG --type file < kubeconfig.yaml
File-type variable from stdin
glab variable set DB_HOST db.prod --scope production
Limit to one environment
glab variable list
List names
glab variable get DB_HOST
Read a value
glab variable export
Dump all as JSON
glab variable delete OLD_KEY
Remove

Raw API api

Authenticated calls to REST or GraphQL for anything glab lacks a command for.

glab api projects/:id/merge_requests --paginate
REST GET; :id resolves to the current project
glab api -X POST projects/:id/issues -f title="From API"
POST with form fields
glab api projects/:fullpath/repository/branches | jq '.[].name'
Pipe JSON to jq
glab api graphql -f query='{ currentUser { username } }'
GraphQL query

Key concepts model

Group
Namespace holding projects and subgroups; permissions and variables inherit downward.
Project
One git repo plus its issues, MRs, CI/CD, registry and wiki.
MR (!123)
Merge request: proposed change from a source to a target branch. Prefix !.
Issue (#42)
Tracked work item. "Closes #42" in an MR closes it on merge.
Pipeline
One run of .gitlab-ci.yml; made of stages, which contain jobs.
Job
A script executed by a runner; produces logs and artifacts.
Runner
Agent that executes jobs. Shared, group or project scoped; matched by tags.
Protected
Branches/tags with push and merge rules. Protected variables only reach these.
Masked
Variable value hidden as [MASKED] in job logs.
Environment
Deploy target (staging, prod) with history and scoped variables.
PAT
Personal access token; scoped, expiring. Project and group tokens exist for bots.
Draft
MR that can't be merged until marked ready.

Git companions git

glab handles GitLab; git still moves the code.

git switch -c feat/retry
New branch
git push -u origin HEAD
Push and track current branch
git push -o merge_request.create -o merge_request.target=main
GitLab push options: open an MR during push
git push -o ci.skip

git fetch origin && git rebase origin/main
Catch up with main
git commit -m "fix: timeout" -m "Changelog: fixed"
Trailer read by glab changelog
