Key concepts

Git tracks snapshots, not diffs. Every commit points to a full tree of your files plus its parent commit(s). Branches and tags are just names pointing at commits.

Repository
The .git folder: every commit, branch, and tag for the project. Clone it and you have the full history locally.
Commit
A snapshot of the staged tree with author, message, and parent pointer(s). Identified by a SHA hash like a1b2c3d.
Staging area (index)
The draft of your next commit. git add copies changes into it; git commit saves exactly what's there.
Branch
A movable pointer to a commit. Committing on a branch moves the pointer forward. Cheap to create and delete.
HEAD
Which commit you have checked out, usually via a branch name. Detached HEAD means it points straight at a commit.
Remote
A named URL for another copy of the repo. origin is the default name for the one you cloned from.
Tracking branch
origin/main is your local record of where main was on the remote at the last fetch. Shown as @{u} (upstream).
Merge vs. rebase
Merge joins histories with a merge commit. Rebase replays your commits on top of another base, giving a straight line but new SHAs.
Fast-forward
When the target has no new commits, merging just slides the branch pointer forward. No merge commit is made.
Stash
A shelf for uncommitted changes so you can switch tasks with a clean working tree.
Tag
A fixed name for a commit, usually a release like v1.4.0. Annotated tags carry a message and author.
Reflog
A local log of everywhere HEAD has been. Your safety net for recovering "lost" commits after a reset or rebase.

Recipes

Common multi-step workflows, in order.

Feature branch to pull request

  1. git switch main && git pull
  2. git switch -c feature/login
  3. Edit, then git add -p and git commit -m "Add login form"
  4. git push -u origin feature/login
  5. Open the PR on GitHub/GitLab. After merge: git switch main && git pull && git branch -d feature/login

Update your branch with latest main

  1. git fetch origin
  2. git rebase origin/main (or git merge origin/main)
  3. On conflict: fix files, git add <file>, git rebase --continue
  4. If you rebased a pushed branch: git push --force-with-lease

Resolve a merge conflict

  1. git status lists files marked "both modified"
  2. Edit each file; remove the <<<<<<< ======= >>>>>>> markers
  3. git add <file> for each resolved file
  4. git commit (merge) or git rebase --continue
  5. Bail out any time: git merge --abort / git rebase --abort

Committed to the wrong branch

  1. git branch feature/fix (save the commit on a new branch)
  2. git reset --hard HEAD~1 (remove it from the current branch)
  3. git switch feature/fix

Recover a "lost" commit

  1. git reflog and find the SHA before the bad reset/rebase
  2. git switch -c rescue <sha> or git reset --hard <sha>

Squash commits before a PR

  1. git rebase -i HEAD~4
  2. Keep the first line as pick, change the rest to squash (or fixup)
  3. Save, edit the combined message, then git push --force-with-lease

Keep a fork in sync

  1. git remote add upstream <original-url>
  2. git fetch upstream
  3. git switch main && git merge upstream/main
  4. git push origin main

Stop tracking a file you meant to ignore

  1. Add the pattern to .gitignore
  2. git rm --cached <file> (keeps it on disk)
  3. git commit -m "Stop tracking <file>"
Tip: git help <command> opens the full manual, and git <command> -h prints a short usage summary.
