Key concepts

mental model

Image

Read-only template: a stack of filesystem layers plus metadata (entrypoint, env, ports). Built from a Dockerfile. Identified by repo:tag or @sha256:digest.

Container

A running (or stopped) instance of an image: image layers + a thin writable layer, isolated by Linux namespaces and limited by cgroups. Disposable by design.

Layer

Each filesystem-changing Dockerfile step (RUN, COPY, ADD) adds a cached layer. Order steps least- to most-frequently-changed to keep builds fast.

Registry & Repository

A registry (Docker Hub, GHCR, ECR, Harbor, a local registry:2) hosts repositories; a repository holds tagged versions of one image.

Tag vs Digest

Tags (:1.27, :latest) are movable labels. Digests (@sha256:…) are immutable content hashes. Pin digests for reproducible deploys.

Volume

Docker-managed persistent storage that outlives containers. Use for databases and state. Bind mounts map a host path instead; tmpfs lives in memory.

Network

User-defined bridge networks give containers DNS by name. host shares the host stack; none isolates. Publish ports with -p to reach from outside.

Dockerfile & Build context

Dockerfile = recipe. Context = the directory sent to the builder (trim with .dockerignore). BuildKit is the default builder.

Compose

Declarative multi-container apps in compose.yaml: services, networks, volumes. Run with docker compose (v2 plugin, space not hyphen).

Context

Which Docker daemon the CLI talks to: local socket, remote over SSH, etc. Switch with docker context use.

Entrypoint vs CMD

ENTRYPOINT is the executable; CMD supplies default args. Args after the image in docker run replace CMD.

PID 1 & signals

The main process is PID 1; the container lives while it runs. stop sends SIGTERM, then SIGKILL after a timeout (default 10s).
